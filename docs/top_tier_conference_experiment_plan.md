# 顶会级别实验计划：多模态双语PRD多智能体生成系统

## 一、实验目标与创新点

### 1.1 核心创新点

1. **多智能体协同架构**：8个专业化Agent通过黑板机制协同工作
2. **双语一致性保证**：中英文生成链路完全对等，Alignment Agent确保一致性
3. **多模态内容生成**：自动生成流程图、界面图、表格等
4. **问题-解决方案空间分离**：明确区分问题陈述与解决方案方向
5. **用户旅程完整性**：完整的用户旅程映射
6. **假设验证机制**：基于假设驱动开发的最佳实践

### 1.2 实验目标

1. **验证系统有效性**：证明多智能体系统优于基线系统
2. **评估组件贡献**：通过消融实验验证各Agent的必要性
3. **质量评估**：使用13个质量指标全面评估生成PRD质量
4. **与真实PRD对比**：使用300份真实中文PRD作为参考标准
5. **统计分析**：使用统计检验验证结果显著性

## 二、实验设计

### 2.1 数据集

#### 2.1.1 基准数据集（输入）

- **规模**：15个Brief样例
- **覆盖**：
  - 14种PRD模板风格（Figma、Asana、Jira、Linear等）
  - 6个领域（金融、电商、医疗、教育、通用、其他）
- **格式**：结构化JSON Brief
- **位置**：`data/benchmark/`

#### 2.1.2 真实PRD参考标准（评估标准）

- **规模**：300份真实中文PRD
- **分类**：
  - **高质量样本**：48个倒推案例 + 22个大厂案例（70个）
  - **领域覆盖**：电商25、社交15、娱乐18、企业服务13、教育10、金融7等
  - **方法论文档**：56个（用于Prompt优化）
- **用途**：
  - S_expert指标参考标准（语义相似度计算）
  - Few-shot学习示例（提升生成质量）
  - 评估基准（结构完整性、内容深度等）
- **位置**：`data/chinese_prds/`

---

### 2.2 实验系统配置

#### 2.2.1 完整系统（Ours）

- **架构**：8个Agent协同工作
  - LeadAnalyst（需求分析）
  - TextGen_CN（中文文本生成）
  - TextGen_EN（英文文本生成）
  - AlignmentAgent（双语对齐）
  - VisionAgent（流程图/界面图生成）
  - TableAgent（KPI/里程碑表格生成）
  - ConsistencyAgent（一致性检查）
  - QualityAgent（质量汇总）
  - Assembler（PRD组装）

- **特点**：
  - 问题-解决方案空间分离
  - 用户旅程完整性保证
  - 假设验证机制
  - 多模态内容生成
  - 双语一致性保证

#### 2.2.2 基线系统（Baselines）

**Baseline 1: TextOnly（单一LLM）**
- **描述**：使用单一LLM生成纯文本PRD，无多模态、无双语对齐
- **实现**：`src/baselines/text_only.py`
- **用途**：验证多智能体系统的优势

**Baseline 2: Template（规则模板）**
- **描述**：固定章节模板 + 简单插值，代表传统文档工具
- **实现**：`src/baselines/template.py`
- **用途**：评估规则系统在复杂场景下的局限

**Baseline 3: Retrieval（检索增强弱多模态）**
- **描述**：使用sentence-transformers检索相似界面/流程，作为弱多模态补充
- **实现**：`src/baselines/retrieval.py`
- **用途**：比较检索式多模态与生成式多模态的差异

#### 2.2.3 消融系统（Ablation Variants）

**Ablation 1: No_Alignment（无双语对齐）**
- **描述**：移除AlignmentAgent
- **假设**：双语一致性将显著下降（S_bi降低）

**Ablation 2: No_Vision（无视觉生成）**
- **描述**：移除VisionAgent
- **假设**：跨模态一致性将显著下降（S_mm降低）

**Ablation 3: No_Table（无表格生成）**
- **描述**：移除TableAgent
- **假设**：表格质量将显著下降（S_tab降低）

**Ablation 4: No_Consistency（无一致性检查）**
- **描述**：移除ConsistencyAgent
- **假设**：结构完整性可能下降（S_comp降低）

**Ablation 5: Async_Queue（异步队列通信）**
- **描述**：使用异步队列通信模式替代黑板机制
- **假设**：黑板机制优于异步队列

**Ablation 6: Mock_Model（Mock模型）**
- **描述**：使用Mock模型替代Qwen模型
- **假设**：真实模型质量显著优于Mock模型

### 2.3 评估指标

#### 2.3.1 基础指标（5个）

1. **S_comp（结构完整度）**：章节覆盖率和内容完整性
2. **S_mm（跨模态一致性）**：文本与图表引用的匹配度
3. **S_tab（表格一致性）**：表格格式和内容质量
4. **S_bi（双语一致性）**：中英文内容长度和语义一致性
5. **S_var（稳定性）**：多次生成结果的方差

#### 2.3.2 扩展指标（8个）

6. **S_sem（语义质量）**：问题陈述清晰度、需求可执行性、术语一致性
7. **S_biz（业务对齐度）**：Goal与KPI一致性、用户需求覆盖度
8. **S_tech（技术可行性）**：技术要求的合理性、约束完整性
9. **S_risk（风险识别）**：风险识别完整性和缓解策略有效性
10. **S_expert（专家对齐度）**：与真实PRD的语义相似度（**核心创新**）
11. **S_ps（问题-解决方案分离度）**：问题陈述与解决方案的区分程度（**创新指标**）
12. **S_uj（用户旅程完整性）**：用户旅程描述的全面性（**创新指标**）
13. **S_hyp（假设验证度）**：假设的明确性和可验证性（**创新指标**）
